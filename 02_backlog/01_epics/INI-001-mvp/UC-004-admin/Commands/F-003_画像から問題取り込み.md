# F-003 画像から問題を取り込む（OCR / AI）

最終更新: 2026-07-14
ステータス: Draft（構想・未実装）
種別: Command / UC-004
関連: [ADR-0004 画像取り込みのAI/OCR方式](../../../../../00_docs/20_tech/20_architecture/adr/ADR-0004_ImageImport-AI-OCR.md)

> 実装は将来。本ドキュメントは実装着手時の設計リファレンス。

## ユーザーストーリー
> 管理者として、教科書やプリントの問題画像をアップロードすると、問題文・級・論点・正解の仕訳（借方/貸方/金額）が自動でフォームに入力され、確認・修正してから登録したい。手入力の手間を減らしたい。

## スコープ / 非スコープ
- スコープ: 仕訳・選択・計算の**文章題**の取り込み。取り込み結果は必ず管理者が確認してから保存。
- 非スコープ（初期）: 手書き文字、精算表・Tフォームなど複雑な表組みの完全自動化。

## アーキテクチャ（推奨: LLM経由・Edge Function中継）

APIキーはブラウザに出さず、Supabase Edge Function に保管して中継する。

```
[管理者ブラウザ]
  1. 画像を選択 / 貼り付け
  2. Edge Function へ送信（base64 もしくは Storage 経由）
        │
        ▼
[Supabase Edge Function]  ← APIキーは環境変数に保管
  3. 画像を AI API (マルチモーダルLLM / OCR) へ送信
  4. 返却 JSON を検証・整形（Zod）
  5. 科目名 → accounts.id へマッピング
        │
        ▼
[管理者ブラウザ]
  6. QuestionEditor のフォームへ自動入力（プレビュー）
  7. 管理者が確認・修正 → 「保存」で questions テーブルへ
```

**原則**: AI出力を直接DBに保存しない。必ず「フォームに入れて人が確認」する 6→7 を挟む。

## データ契約（LLMに返させるJSON）

`QuestionEditor` のフォーム項目と1対1で対応させる。

```json
{
  "grade": "grade_3",
  "topic": "仕入・売上",
  "difficulty": 1,
  "type": "journal",
  "body": "商品10,000円を仕入れ、代金は現金で支払った。",
  "explanation": "...",
  "lines": [
    { "side": "debit",  "account": "仕入", "amount": 10000 },
    { "side": "credit", "account": "現金", "amount": 10000 }
  ]
}
```

- `type` を自動判定させれば、仕訳/選択/計算のどのフォームを埋めるかまで自動化できる。
- `account` は**科目名（文字列）**で受け取り、サーバー側で既存 `accounts` に照合する。

## 検証レイヤ（実装の肝。既存資産を流用）

| 検証 | 内容 | 流用元 |
|------|------|--------|
| スキーマ検証 | 型・enum（grade/side/type）を Zod で検証、壊れた出力を弾く | 新規 |
| 貸借一致 | 借方合計＝貸方合計 かつ > 0 | `QuestionEditor` の balance 判定 |
| 科目マッピング | 科目名 → `accountMap` で照合。未知なら「勘定科目管理」へ追加を促す | `data/accounts` |
| 金額正規化 | 「10,000円」「10000」等の表記ゆれを数値へ | 新規 |

## 受け入れ基準（Draft）
- [ ] 画像をアップロード/貼り付けできる（編集モーダルに「画像から取り込む」導線）。
- [ ] 取り込み結果がフォームにプレビュー入力され、管理者が修正できる。
- [ ] 貸借不一致・未知科目・スキーマ不正は保存前に警告される。
- [ ] APIキーがクライアントに露出しない（Edge Function 経由）。
- [ ] admin ロールのみ実行可能（RLS / 認可）。

## 段階的な進め方
1. **mock**: 「画像から取り込む」UI＋ダミー応答でフォーム自動入力の体験を作る（AIなし）。
2. **実装**: Edge Function で実APIに差し替え。まずは仕訳・文章題のみ対応。
3. **拡張**: 選択・計算、複雑な表組みへ段階的に対応。
