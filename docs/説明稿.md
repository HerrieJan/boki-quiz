# 簿記クイズ 説明稿

読む時間の目安: 7〜8分（ゆっくりで約9分）
【】は画面操作。操作中は読まなくてよい。
時間が押したら「4. 管理画面」は2文で切り上げる。

---

## 1. 何を作ったか（1分）

React入門の個人開発で、簿記の練習アプリを作りました。名前は「簿記クイズ」です。

簿記には3級、2級、1級があって、仕訳の問題が多いです。紙に書く代わりに、画面で借方と貸方を組み立てて、その場で合っているか分かるようにしたかったので、この題材にしました。

使ったものは、React、TypeScript、Vite、Tailwind CSS です。ドラッグには dnd-kit というライブラリを足しました。画面の部品はコンポーネントに分けています。入口は `App` で、ここは「問題を解く」と「問題を管理」の切り替えだけを持っています。切り替えは `useState` です。

問題のデータは、まだサーバーにはありません。`src/data/questions.ts` の配列です。TypeScript で、仕訳・選択・計算の3種類を、1つの `Question` 型として扱えるようにしています。

## 2. 問題を解く画面（2分）

【「問題を解く」を見せる。左の級と論点を変える】

左が問題一覧、右が今解いている問題です。一覧は `questions` を `filter` して出しています。級と論点の両方に合うものだけ残します。論点の選択肢は、今選んでいる級に存在する論点だけです。ここは、級が変わるたびに計算し直したくないので `useMemo` にしています。絞り込みで、今開いている問題が一覧から消えたときは、先頭の問題を選び直しています。

一覧の各項目は `map` で描いていて、`key` には問題の id を渡しています。

右の `QuizPage` は、問題が1問分です。問題を切り替えるとき、前の入力が残らないように、`key` に問題 id を付けています。id が変わると、このコンポーネントは最初から作り直されます。

問題の種類で、出す入力を変えています。仕訳、選択、計算です。これは `question.type` を見て、条件分岐でコンポーネントを出し分けています。

## 3. 仕訳・採点・間違えた問題（3分）

【仕訳の問題を開く】

仕訳は2通りの入力があります。ドラッグと、セレクトです。これも state で切り替えています。

【科目を借方へ、金額をその行へドロップする】

ドラッグ側では、下に勘定科目と金額を並べています。正解だけでなく、関係ない科目と金額も少し混ぜています。同じ級の科目だけを混ぜるので、3級の問題に1級の科目は出ません。借方と貸方で同じ金額が必要なことがあるので、金額は「種類ごと1個」ではなく「行の数だけ」作っています。たとえば 10,000 が借方と貸方の両方にある問題では、10,000 のチップが2つ出ます。

使っているのは dnd-kit の `DndContext` です。チップは `useDraggable`、置く場所は `useDroppable` です。ドロップしたとき、落ちた場所の id を見て、借方か貸方か、金額の枠かを決めています。置いたチップは下の候補から消えて、行を消すと戻ります。

【「採点する」を押す】

採点は画面の中には書いていません。`src/domain/scoring.ts` の関数です。画面は「答えを作って渡す」だけにしました。

仕訳の正解は、並び順を見ていません。借方どうし、貸方どうしで、「科目と金額」の組み合わせが同じなら正解です。選択問題は、選んだ選択肢の id が正解と一致するかです。計算問題は、入力した数と正解の差が、許容誤差以内かです。

【間違えて「残す」。その後「間違えた問題」を開く】

間違えたときは、残すか聞いています。残した id の一覧は、`QuizPage` ではなく親の `QuizApp` が持っています。`QuizPage` は問題が変わるたびに作り直されるので、ここに置くと消えてしまうからです。子から親へは、`onAddWrong` のような関数を props で渡しています。

この一覧は `useEffect` で localStorage に書いています。`wrongIds` が変わったときだけ保存します。最初に開くときは localStorage から読みます。なので、再読み込みしても残ります。サーバーには送っていません。一覧から削除もできます。もう一度解いて正解したら、外すか聞きます。

## 4. 管理画面（1分半）

【「問題を管理」を開く。新規作成は開いて、借方と貸方を少し見せて閉じる】

管理画面も同じアプリの中です。問題の一覧、追加、編集、複製、削除と、勘定科目の追加ができます。入力は、普通のフォームです。値は state に入れて、入力のたびに state を更新する、制御された input です。

仕訳を保存するときは、借方の合計と貸方の合計が同じで、0より大きいときだけ保存ボタンが押せます。

この画面の追加や削除は、`useState` の配列を書き換えているだけです。localStorage には入れていません。ページを更新すると、最初のサンプル問題に戻ります。

## 5. まとめ（1分）

今回練習したのは、次のことです。

- 画面をコンポーネントに分ける
- `useState` で、今の画面、選んでいる問題、入力、採点結果を持つ
- 子で持つと消える state は、親に上げる
- 配列を `filter` と `map` して一覧を出す
- 問題の型を TypeScript で分ける
- 採点は画面から離した関数にする
- ブラウザに残したいものだけ localStorage に入れる

まだできていないのは、ログインと、問題をデータベースに保存することです。管理画面の変更が更新で消えるのは、そのためです。以上です。

## 想定質問

聞かれたところだけ答えればよい。全部覚える必要はない。

### なぜ React にしたのですか

画面の一部だけを部品にして、データが変わったところを描き直せるからです。問題を切り替えても、ヘッダーまで自分で消して書き直す必要がありません。コースが React だったので、練習も React で作りました。

### コンポーネントとは何ですか

見た目と、その部分の処理をまとめた関数です。たとえば `QuizPage` は1問分、`ResultPanel` は採点結果の表示だけです。親から `question` のような props をもらって描きます。

### props と state の違いは

props は親から渡される値で、子の中では書き換えません。state は、そのコンポーネントが自分で持って、`setState` で変える値です。変わると、その部分が再描画されます。選んでいる問題は親の state、入力中の行は `QuizPage` の state です。

### なぜ間違えた問題は親が持つのですか

`QuizPage` には `key={問題id}` を付けています。問題を変えると、入力を空にするためにコンポーネントが作り直されます。ここに一覧を置くと、問題を変えた瞬間に消えます。消えてほしくないので、親の `QuizApp` に置いて、追加と削除の関数だけ子に渡しています。

### key は何のためですか

React がリストの各要素を見分けるための名前です。id を付けています。index だけだと、削除したときに別の行と取り違えることがあります。`QuizPage` の key はリスト用ではなく、問題が変わったら入力 state をリセットするために付けています。

### useEffect は何をしていますか

`wrongIds` が変わったあとで、localStorage に保存しています。描画そのものではなく、描画の外側の処理です。最初の読み込みは `useState` の初期値でやっています。

### useMemo は必要でしたか

級や論点を変えたときだけ、一覧を絞り込むために使いました。問題数が少ないので、なくても動きます。毎回 filter すると読みにくいので、依存する値が変わったときだけ計算する、という書き方の練習です。

### 採点の仕方を、もう少し具体的に

仕訳は、1行を「借方か貸方、科目 id、金額」の文字列にして、その個数を数えています。正解と解答で、その個数が同じなら正解です。順番が違っても正解になります。同じ行が2つある場合も、個数で見ているのでずれません。

選択は、正解の id の集合と、選んだ id の集合が同じかです。計算は、差の絶対値が許容誤差以下かです。今のサンプルは誤差 0 なので、ぴったり一致です。

### ドラッグで、どこに落ちたかはどう分かりますか

dnd-kit が、ドロップ先の id をくれます。借方の領域の id は `debit`、貸方は `credit`、金額の枠は `amt-slot:` で始まる id です。科目を借方か貸方に落としたら行を追加して、金額を枠に落としたらその行の金額を入れます。

### 10,000 が1つしか出ない問題と、2つ出る問題の違いは

正解の行ごとにチップを作っています。借方 10,000、貸方 10,000 なら、10,000 は2つです。1種類につき1個だけだと、片方に置くともう片方に置けなくなります。

### データはどこに保存していますか

問題文と正解は、ソースコードの配列です。間違えた問題の id だけ、ブラウザの localStorage です。管理画面で追加した問題はメモリ上の state だけで、更新すると消えます。

### なぜデータベースにしなかったのですか

今回の範囲は、画面と state の練習にしたからです。保存先を足すと、ログインや権限も必要になります。配列にしておいたので、あとから取得処理に差し替えやすいです。

### 管理画面の削除は、本当に消えているのですか

その場の state からは消えます。元の配列ファイルは書き換えていないので、更新すると戻ります。デモでは「今の画面上では消える」と説明します。

### TypeScript を入れて、何が楽になりましたか

問題が仕訳なのか選択なのかを、型で分けられました。`question.type` が `journal` の分岐の中では、正解の行がある、とコンパイラが分かります。ありえない組み合わせを、実行前に気づけます。

### Tailwind は何ですか

CSS をクラス名で付けるやり方です。たとえば枠は `border`、余白は `p-4` です。別の CSS ファイルに名前を増やさずに、コンポーネントの中で見た目を書いています。

### Vite は何をしていますか

開発中のサーバーと、本番用のビルドです。`npm run dev` で画面を開いて、保存するとその場で更新されます。`npm run build` の前に `tsc` で型も見ています。

### React Router は使いましたか

使っていません。ページが2つだけなので、`useState` で「今どっちの画面か」を持っています。URL で共有したいページが増えたら、そのときにルーターを足します。

### 次にやるとしたら

問題の保存です。管理画面の変更が更新で消えないようにする、が先です。その次がログインです。採点の考え方は、今の関数のまま使えます。
